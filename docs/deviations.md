| R10 | — | **Strictly causal gate granularity** (`spectre_torch/r10_causal.py` (formerly `spectre_torch/chunked_causal.py`)): the window is split into `causal_chunks` chunks (default 4 → 256-token chunks at n=1024); chunk `c`'s spectral kernel is computed from the query mean of *strictly earlier* positions only (`causal_query_pools`), so chunk 0 gets a zeros descriptor and therefore the learned cold-start kernel. Both variants take a `causal_chunks` argument: `0` reproduces R5/R9 exactly, `≥2` enables R10. Run: `train.py --r10` → `checkpoints/best-r10.pt`, `train.py --official-causal-r10` → `checkpoints/best-official-causal-r10.pt`. Per-chunk mixing is a zero-padded linear convolution with an exact raw-tail carry (one bounded FFT per chunk, `chunked_causal_conv`), keeping the O(N log N) cost. | **A second future leak that the earlier "causal" labels missed** (Issue #3). The R5/R9 layers mixed causally, but the *gate descriptor* pooled queries over the whole window, so the kernel itself moved whenever any future token moved — measured 0.49 output delta under a randomized gate. The committed causality tests were vacuous because they used an all-pass or near-identity gate, which is constant and therefore insensitive to its input. Fixing the gate requires per-chunk kernels, which multiplies the conv-path FFT cost by `causal_chunks`; 4 chunks (256 tokens) keeps that overhead bounded and gives each kernel enough past context to be non-degenerate. The official variant additionally replaces DCT pooling with the cumulative-mean descriptor the vendored `decode_step` already uses (`sum_q / cache.N`), which removes a train/decode mismatch in the original code. Chunking at fixed `causal_chunks` means the effective kernel granularity no longer tracks `n_fft`; a block-diagonal-from-chunk-0 initialization would be the natural refinement if per-chunk kernels prove too weak. |
